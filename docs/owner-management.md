# Управление ссылками 0.2.0

Публичные ссылки: https://n-0.ru/код. Создание и редактирование: https://links.n-0.ru/.
Админка и страница входа переключаются между русским и английским; выбор сохраняется в браузере.

## Безопасность и конфигурация

Управление использует отдельную сессию Spring Security и CSRF, требует HTTPS и точный host.
Задайте SMARTLINKS_OWNER_USERNAME и SMARTLINKS_OWNER_PASSWORD_HASH (DelegatingPasswordEncoder, например bcrypt).
Пустые значения закрывают вход. API-ключ и хеш пароля не передаются браузеру.
За доверенным прокси задайте SERVER_FORWARD_HEADERS_STRATEGY=framework; прокси обязан
перезаписывать Forwarded/X-Forwarded-* и ограничивать доступ к управлению точным поддоменом.
Прямой доступ к приложению в обход доверенного прокси должен блокироваться сетью.
DateRange использует Europe/Moscow независимо от часового пояса процесса; поля интерфейса — МСК.
Сессии Spring Session хранятся в Redis с префиксом spring:session и доступны всем репликам.
Это сохраняет фактическое пространство сессий предыдущего выпуска на Spring Boot 4.1.
Ссылки интерфейса относительные: поддерживается server.servlet.context-path.

## Создание и редактирование

POST /manage/api/smartlinks возвращает 201 с id и url. Занятый код даёт 409, без перезаписи.
GET /manage/api/smartlinks/{id} читает определение и возвращает сильный ETag и Content-Location
с публичным URL. PUT на тот же путь требует If-Match с точным ETag последнего чтения.
Код остаётся неизменным; PUT заменяет правила целиком и возвращает новое определение и ETag.
Без If-Match — 428, со слабым, составным или wildcard значением — 400, с устаревшей версией — 412.
Неизвестный код — 404; PUT не создаёт новую ссылку. После конфликта перечитайте ссылку.

Создание и редактирование разделены на сценарии и используют общий валидатор определения.
Redis Lua сравнивает версию и заменяет запись одной атомарной операцией, сохраняя TTL.
Старые записи без версии имеют ETag "0" и редактируются без миграции данных.
Редиректор читает актуальную запись из Redis: локальный L1-кэш удалён, поэтому другая реплика
не продолжает отдавать прежнее назначение после завершившегося редактирования.
Параллельный запрос, прочитавший запись до PUT, может завершиться со старым назначением.

Правила сохраняют порядок, первое совпадение и последний запасной адрес. Интерфейс поддерживает
несколько устройств и языков, диапазоны дат и перестановку правил; дополнительные аргументы сохраняются.
Неизвестный предикат блокирует редактирование через форму, чтобы не потерять условия.
Валидация остаётся на сервере. Обычная ссылка содержит только запасное правило.
SMARTLINKS_RESERVED_IDS добавляет служебные коды через запятую к общему запрету для обоих API.
Удаление и статистика не входят в выпуск. Прежние GET /s/{id} и POST /api/smartlinks с X-API-Key сохраняются.

## Маршрутизация и Kubernetes

В production главный сайт на Blue сохраняет свои страницы, файлы и /api/; только свободный
одноуровневый GET/HEAD переписывается в /s/{id} и передаётся SmartLinks на Red.
Поддомен перенаправляет / на /manage/ и проксирует только /manage/, сохраняя метод, сессию и CSRF.
Redis, actuator и прежний API остаются внутренними. Реализация внешнего прокси:
[N0Site deploy/nginx.conf.template](https://github.com/krotname/N0Site/blob/main/deploy/nginx.conf.template).

k8s/ingress.yaml — пример внутреннего backend ingress для этой схемы, а не замена сайта.
Создайте TLS secret smart-links-tls с SAN links.n-0.ru и smartlinks.n-0.ru;
направляйте основной домен на сайт, а не прямо на backend ingress. Для владельца используется
точный host links.n-0.ru, совпадающий с конфигурацией Deployment и проверкой ManagementOriginFilter.
Создайте Secrets smart-links-owner (username, password-hash) и smart-links-api-key (api-key).
Перед применением Deployment замените образ на проверенный digest выпуска; production управляется GitOps.
Пример требует ingress-nginx, который завершает TLS и перезаписывает недоверенные forwarded headers.
Проверка после применения: /manage/login по HTTPS, создание и чтение, /код → 302,
/неизвестный-код → 404, а страницы сайта и /api/ продолжают обслуживаться сайтом.

## Проверки и производительность

TDD: сначала отрицательные HTTP-контракты; затем unit-тесты сценария, MVC и реальные Redis-тесты,
включая гонку двух редакторов и чтение другой репликой. Node test runner проверяет RU/EN и
преобразование формы без потери условий. Сборка выполняется ARC с постоянным кэшем.
Лимиты тела/JSON, URL, числа правил, Redis timeouts и пул соединений ограничивают стоимость запроса.
Исторические замеры в README относятся к прежней реализации с L1-кэшем;
они не доказывают пропускную способность 0.2.0. Новые показатели требуют отдельного замера.
Стабильные OCI-теги публикуются только по соответствующему Git-тегу vMAJOR.MINOR.PATCH;
main публикует sha/latest и не перезаписывает тег выпуска.
